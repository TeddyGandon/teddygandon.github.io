I started writing PHP and ActionScript for a small studio in 2007. The stack has changed more or less completely since then — Flex is gone, jQuery came and went, the frameworks I use daily didn't exist yet. What hasn't changed is the thread running through all of it: the same curiosity about how a system actually works, applied first to code, later to teams.

## The shape of it

Five roles, in short:

- A **developer**, learning that shipping something ugly on time teaches you more than polishing something late.
- A **CTO in a startup**, learning that architecture decisions are really business decisions wearing a technical costume.
- A **senior backend engineer**, learning to write systems for the person who reads the code six months later, not for the compiler.
- A **team lead**, learning that the best technical decision is worthless if the team can't move with it.
- An **engineering manager**, learning that most of the job is removing what's in people's way, not adding what you think they need.

## What carried over

Problem solving didn't change shape — it just moved up a level, from "why does this query time out" to "why does this team keep missing the same kind of deadline." Curiosity is still the same instinct: don't accept the first explanation, ask what's underneath it. Communication went from a nice-to-have to the actual job.

If there's a single throughline, it's this: every role rewarded slowing down enough to understand the real problem before reaching for a fix. That was true writing Flex applications in 2009, and it's true running a team today.
